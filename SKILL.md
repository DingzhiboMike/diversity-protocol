# Diversity Protocol

Когда нужно сгенерировать несколько вариантов одной задачи — заголовков, формулировок позиционирования, упаковок продукта, концептов, ракурсов — большинство систем (и людей) выдают восемь обёрток одной мысли. Меняются слова, порядок, интонация — суть остаётся одна.

Этот протокол — про то, как этого избежать. Источник: метод **String Seed of Thought** (SSoT) от Sakana AI, ICLR 2026. Принцип переведён в рабочий инструмент для двух контекстов: промпт для LLM и редакторская дисциплина для человека или AI-ассистента.

## Согласование

Если пользователь сам не просил протокол (не сказал «diversity protocol», «SSoT», «нужно разнообразие»), спроси одной фразой, прежде чем применять: протокол меняет форму ответа — у каждого варианта появляется названная ось. Без вопроса применяй в трёх случаях: пользователь попросил явно; протокол вызывает другой скилл, который уже согласовал это с пользователем; правишь собственный вывод по Режиму 2 (это внутренняя дисциплина, форма ответа не меняется).

## Когда применять
- Запрос требует ≥3 вариантов одного типа артефакта
- Запрос на «дай альтернативы», «придумай ещё», «как ещё это можно подать»
- Жалоба «AI повторяется» или «всё одно и то же»
- Любая задача на ideation, brainstorming, creative pool
- Когда сам видишь, что выдал три варианта одной природы — это сигнал применить протокол к собственному выводу

## Когда НЕ применять

- Задача с одним правильным ответом (факт, расчёт, классификация)
- Задача требует строгого следования формату/шаблону
- Reasoning-задача с конкретным выводом (математика, логика, дебаг)
- Диагностика — нужен один точный диагноз, не три размытых
- Структурные документы, требующие полноты (матрица витрин, карта стейкхолдеров, roadmap) — там нужна полнота, не выбор

## Режим 1: SSoT-блок для LLM

Когда задача делегируется модели (Claude, GPT, DeepSeek и т.п.) — в системный промпт или в начало пользовательского промпта вшивается готовый блок.

**Готовый блок (русский):**

```
Сначала сгенерируй сложную случайную строку между тегами <random_string> и </random_string>. Потом используй эту строку как основу для всех случайных решений внутри тегов <thinking> и </thinking>. После этого выдай финальный ответ между тегами <answer> и </answer>. Ответ должен быть единственным, уникальным и максимально разнообразным.
```

**Готовый блок (английский, оригинал из статьи):**

```
You must produce exactly one unique and diverse answer. To do this, first generate a complex random string between <random_string> and </random_string>, and manipulate this string to guide any stochastic decisions within <thinking> and </thinking> tags. Then, provide your final answer, enclosed within <answer> and </answer> tags.
```

**Важно: один вызов — один ответ.** Блок из статьи рассчитан на то, что модель выдаёт *один* ответ за вызов, а разнообразие появляется между независимыми вызовами. Если нужно N вариантов — сделай N отдельных вызовов с этим блоком. Если нужно N вариантов в одном ответе, блок не подходит: используй Режим 2 (оси разнообразия) прямо в промпте.

**Куда вшивать:**
- В custom instructions / system prompt — если задача повторяющаяся
- В начало пользовательского промпта — если разовая задача
- НЕ дублировать в нескольких местах одного промпта

**Калибровка:**
- Один блок на промпт, не больше
- Не комбинировать с просьбой «будь разнообразнее» — дублирование снижает эффект
- Не комбинировать с очень высокой температурой (>1.5) — конфликт сигналов
- Сильнее всего работает на моделях с режимом рассуждения (extended thinking и аналоги)
- На маленьких моделях без reasoning эффект ослаблен или отрицательный

## Режим 2: Редакторский протокол для человека или AI-ассистента

Когда варианты генерирует не отдельная модель, а сам ассистент в рамках разговора (или человек, проектирующий артефакты) — SSoT превращается в дисциплину мышления.

**Главное правило:** перед каждым следующим вариантом задаёшь вопрос — *«По какой смысловой оси этот вариант разнится от предыдущих?»*. Не «другие слова», не «другая интонация» — другая ось. Если не можешь назвать ось — вариант не считается, переписываешь.

**Якорь честности:** в финале блока с вариантами одной строкой называешь ось каждого. Если для какого-то варианта не можешь назвать ось — выкидывай, он декоративный.

**Anti-pattern:** «дай 5 вариантов хедлайна» и в ответ пять интонаций одной мысли — «Почему X», «Как X», «X: гайд», «5 уроков X», «X за неделю». Это не пять — это один.

## Оси разнообразия для типичных задач

Это ориентир, не лимит. Главное — каждая ось радикально меняет природу варианта, а не его упаковку.

**Хедлайны / заголовки:**
- Жанр: провокация / обещание / сцена / цифра / противоречие / вопрос / антитеза
- Угол подачи: разоблачение / приглашение / предупреждение / признание
- Точка отсчёта: личный опыт / общая практика / контр-пример / прогноз

**Позиционирование:**
- Сегмент (кому помогаешь)
- Pain (от чего избавляешь)
- Gain (куда переводишь)
- Delta (чем отличаешься от соседей)
- Category (какую категорию занимаешь)

**Упаковка экспертизы / продуктов:**
- Аудитория (под какой сегмент)
- Глубина обязательств (лекция / курс / advisory / mentorship)
- Цена (фронт / мидл / бэк)
- Формат потребления (чтение / аудио / синхрон / асинхрон)
- Угол ценности (научишься делать / избежишь ошибки / получишь сообщество / станешь видимым)

**Концепты / креативные идеи:**
- Метафора в основе (механика / биология / архитектура / музыка / война)
- Эмоциональный тон (страх / любопытство / гордость / стыд / триумф)
- Жанровая отсылка (триллер / комедия / документалка / эссе)
- Точка входа (с конца / с середины / с детали / с парадокса)

**Ракурсы статьи / поста на одну тему:**
- Историческая (как было раньше)
- Системная (как устроено сейчас)
- Прогностическая (куда идёт)
- Контр-кейс (где не работает)
- Практическая (что делать сегодня)
- Личная (мой опыт с этим)

---

## Финальный чеклист (применяешь перед выдачей)

- [ ] Каждый вариант имеет именованную ось разнообразия
- [ ] Ни одна ось не повторяется между вариантами
- [ ] Ни один вариант не является переформулировкой соседнего
- [ ] Если применялся SSoT-блок — он стоит один раз, в начале промпта
- [ ] Anti-pattern «обёртки одной мысли» проверен и отсутствует

---

## Связь с другими скиллами

- **prompt-optimizer** — вызывает Diversity protocol (Режим 1) для multi-output задач, вшивает SSoT-блок в финальный промпт
- **expert-productizer** — может вызывать Режим 2, когда нужно ≥3 вариантов позиционирования / упаковки / монетизации
- **author-in-residence** — может вызывать Режим 2, когда нужны варианты заходов, заголовков, финалов
- **creative-director** — вызывает Режим 2 при генерации концептов, плюс Режим 1 если делегирует ideation модели
- **pub-critic** — может использовать оси разнообразия для диагностики: «у тебя пять вариантов одной мысли, нет осей»
